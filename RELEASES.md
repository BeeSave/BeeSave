# Выпуски BeeSave и будущие обновления

Публичный репозиторий: https://github.com/BeeSave/BeeSave.

Исходники приложения находятся в ветке `main`. Версии приложения отмечаются тегами `v<версия>` и публикуются в GitHub Releases. Первый выпуск BeeSave — `v1.0.1`, сборка 3; macOS 26+, Apple Silicon.

## Сборка выпуска

```sh
./scripts/build_release.sh
```

Версия архива берётся из собранного `Info.plist`. Скрипт создаёт `Dist/BeeSave-<версия>-arm64.zip` и файл SHA-256. Перед публикацией нужно выполнить локальные тесты и проверить подпись распакованного приложения.

## Контракт обновления

В каждом стабильном выпуске должны быть вложения с постоянными именами:

- `BeeSave-macos-arm64.zip` — приложение для Apple Silicon;
- `BeeSave-macos-arm64.zip.sha256` — контрольная сумма архива;
- `latest.json` — схема 1, версия, номер сборки, минимальная macOS, архитектура, тег, ссылка на архив конкретного выпуска и его SHA-256.

Постоянная точка чтения метаданных: https://github.com/BeeSave/BeeSave/releases/latest/download/latest.json. Скачивание последнего стабильного приложения: https://github.com/BeeSave/BeeSave/releases/latest/download/BeeSave-macos-arm64.zip. Ссылки конкретного выпуска содержат тег; это позволяет метаданным и архиву ссылаться на одну версию.

Начиная с выпуска 1.1.0, сборка 5, доступно **BeeSave → Проверить обновление**. Клиент читает последний стабильный Release через GitHub API, затем `latest.json` конкретного тега; сравнивает версию/сборку и совместимость macOS/arm64. После нажатия «Скачать обновление» архив загружается с ограничением размера, проверяется по SHA-256 и сохраняется через системный диалог. Установка текущей ad hoc-поставки выполняется вручную через Finder. Финансовые данные, пароли, ключи и резервные копии не передаются в GitHub.

Скрипт `build_release.sh` создаёт все три постоянных вложения автоматически из построенного Info.plist и фактического архива. SHA-256 проверяет целостность относительно метаданных GitHub и не заменяет доверенную подпись издателя. Приложение не распаковывает и не запускает загруженный код, не меняет sandbox или Gatekeeper. Перед ручной заменой завершите BeeSave; сохраните прежнюю копию приложения для возврата при ошибке запуска. Новая локальная сборка не считается опубликованным GitHub Release до отдельной публикации.

Текущий выпуск подписан ad hoc для локальной разработки и не нотариализован. Для полноценного распространения и автоматической установки нужны Developer ID, нотариализация и проверенный механизм доверия.

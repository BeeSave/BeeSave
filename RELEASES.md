# Выпуски BeeSave и будущие обновления

Публичный репозиторий: https://github.com/BeeSave/BeeSave.

Исходники стабильной 1.2.0 закреплены тегом `v1.2.0`; актуальный протокол находится в ветке `codex/update-install-1-2-0`. Версии приложения отмечаются тегами `v<версия>` и публикуются в GitHub Releases. Первый выпуск BeeSave — `v1.0.1`, сборка 3; macOS 26+, Apple Silicon.

## Сборка выпуска

```sh
./scripts/build_release.sh
```

Кандидат 003 — **1.2.0/build 6**, Apple Development Team `7VXLA38J58`. Sparkle 2.10.0 собирается из закреплённого commit с патчами сетевого и пакетного контракта; все вложенные компоненты подписываются перед Embed & Sign. Library Validation включена. Исходный архив и хеш записаны в `Vendor/Sparkle/lock.json`; лицензии входят в framework.

Версия берётся из готового `Info.plist`. Скрипту нужна папка `bin` проверенного официального дистрибутива Sparkle (`BEESAVE_SPARKLE_TOOLS`). Он создаёт read-only DMG с `BeeSave.app` и ссылкой Applications, подписанный `appcast.xml`, совместимый ZIP, две SHA-256 и `latest.json`. Постоянный ключ Ed25519 хранится в Связке ключей под account `BeeSave-releases-v1`; в приложении находится только публичный ключ. Утилите подписи может понадобиться штатное разрешение на этот ключ. Секрет не экспортируется в исходники или артефакты.

## Контракт обновления

В каждом стабильном выпуске должны быть вложения с постоянными именами:

- `BeeSave-macos-arm64.zip` — приложение для Apple Silicon;
- `BeeSave-macos-arm64.zip.sha256` — контрольная сумма архива;
- `latest.json` — схема 1, версия, номер сборки, минимальная macOS, архитектура, тег, ссылка на архив конкретного выпуска и его SHA-256.
- `BeeSave-macos-arm64.dmg` — приложение для первой установки и последующих обновлений Sparkle;
- `BeeSave-macos-arm64.dmg.sha256` — контрольная сумма DMG;
- `appcast.xml` — Ed25519-подписанный feed одного конкретного выпуска, с подписью DMG, версией/build и платформой.

Постоянная точка чтения метаданных: https://github.com/BeeSave/BeeSave/releases/latest/download/latest.json. Скачивание последнего стабильного приложения: https://github.com/BeeSave/BeeSave/releases/latest/download/BeeSave-macos-arm64.zip. Ссылки конкретного выпуска содержат тег; это позволяет метаданным и архиву ссылаться на одну версию.

Начиная с выпуска 1.1.0, сборка 5, доступно **BeeSave → Проверить обновление**. Клиент читает последний стабильный Release через GitHub API, затем `latest.json` конкретного тега; сравнивает версию/сборку и совместимость macOS/arm64. После нажатия «Скачать обновление» архив загружается с ограничением размера, проверяется по SHA-256 и сохраняется через системный диалог. Установка текущей ad hoc-поставки выполняется вручную через Finder. Финансовые данные, пароли, ключи и резервные копии не передаются в GitHub.

Скрипт `build_release.sh` создаёт все три постоянных вложения автоматически из построенного Info.plist и фактического архива. SHA-256 проверяет целостность относительно метаданных GitHub и не заменяет доверенную подпись издателя. Приложение не распаковывает и не запускает загруженный код, не меняет sandbox или Gatekeeper. Перед ручной заменой завершите BeeSave; сохраните прежнюю копию приложения для возврата при ошибке запуска. Новая локальная сборка не считается опубликованным GitHub Release до отдельной публикации.

Абзацы выше о ручной установке описывают опубликованную 1.1.0. В версии 1.2.0 кнопка **«Обновить и перезапустить»** использует Sparkle: до запуска установщика сохраняются исходный ciphertext бюджета и прежний пакет, завершаются формы и записи. Первое обновление с 1.1.0 пользователь устанавливает из DMG вручную; последующие поддерживаются из приложения. Developer ID и нотариализация не входят в согласованный профиль; Apple Development не отменяет проверки Gatekeeper.

Перед стабильной публикацией обязательны [IAC-01–18](specs/changes/003-update-install.md), все регрессии и сквозная приёмка на macOS 26/27 в отдельном профиле: первый запуск с реальным карантином, Open Anyway, A → B → C без повторного подтверждения, сохранность бюджета и проверенный возврат. Подпись DMG/feed и локальные тесты отдельно не закрывают эти критерии. По последнему поручению заказчика от 06.10.2026 подготовлена предварительная публикация **v1.2.0/build 6** для испытаний с явным статусом **Pre-release**. 06.10.2026 после самостоятельной проверки заказчик признал эту же сборку стабильной. Выпуск переведён из Pre-release в Latest; `/releases/latest` выбирает 1.2.0. Байты вложений и тег не меняются. Неподтверждённые в автоматизированном протоколе системные сценарии не объявляются выполненными этим решением. Текущий статус — [протокол 003](specs/changes/003-update-install-validation.md), описание — [1.2.0](specs/releases/1.2.0.md).

Кандидат поддерживает macOS 26.0 и новее, включая 27; SDK сборки — 27.0. Заказчик выполняет нативную проверку самостоятельно по [инструкции](specs/changes/003-update-install-user-test.md). Для проверки на 27 устанавливать macOS 26 не требуется.

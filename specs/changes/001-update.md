# 001 — Обновление BeeSave из GitHub по кнопке

Дата: 4 октября 2026 года. Базовая спецификация: `SPEC.md` v1.0.
Источник выпуска: публичный репозиторий организации [BeeSave/BeeSave](https://github.com/BeeSave/BeeSave).
Статус: реализовано и проверено в объёме текущей локальной поставки. План и протокол проверки: `specs/changes/001-update-plan.md`.

## Цель и решение для текущего выпуска

Пользователь выбирает «BeeSave → Проверить обновление». Приложение проверяет последний стабильный GitHub Release, сообщает результат и предлагает скачать новую совместимую версию. Архив проверяется и сохраняется в выбранный пользователем файл; Finder показывает его для установки.

Текущая поставка подписана ad hoc, не нотариализована и использует App Sandbox. Поэтому в этом изменении установка завершается вручную: распаковать архив, завершить BeeSave, заменить прежнее приложение, открыть новую версию. Самозамена и автоматический перезапуск не включены. Вопрос о способе установки направлен заказчику; в отсутствие ответа выбран предложенный вариант для текущей локальной сборки. Полностью автоматическая установка требует следующего изменения спецификации с отдельным механизмом доверия и установки.

## Diff базовых требований

Текст `SPEC.md` сохраняется как база. При совместном чтении этот документ заменяет только перечисленные ниже положения.

### GEN-04 — заменить

Разрешён внешний обмен по HTTPS для валютных курсов/справочников и, по явной команде пользователя, для получения сведений о выпуске и архива приложения из BeeSave/BeeSave. Финансовые операции, суммы, названия счетов, категории, проекты, бюджеты, пароли, ключи и резервные копии наружу не передаются. Телеметрии, облачной синхронизации, серверного восстановления и автоматических фоновых проверок обновлений нет.

### GEN-05 — дополнить

В системном меню «BeeSave», после «О BeeSave», доступен пункт с точным названием «Проверить обновление». Он открывает отдельное окно и запускает проверку. Для проверки не требуется разблокировать бюджет.

### TECH-06 — дополнить

Для механизма обновления используется отдельная эфемерная сессия без cookies, кеша и пользовательских учётных данных. API: `https://api.github.com/repos/BeeSave/BeeSave/releases/latest`. Сведения о конкретном выпуске и архив доступны только через `https://github.com/BeeSave/BeeSave/releases/download/<tag>/…`. Допустимы HTTPS-редиректы на точные домены GitHub `release-assets.githubusercontent.com` и `objects.githubusercontent.com`. Системная проверка TLS не отключается. Запросы не содержат GitHub-токенов или данных бюджета.

Тайм-аут ожидания сетевых данных — 15 секунд; предельное время одной передачи — 300 секунд, включая большой архив. Это исключение к прежнему ограничению общего времени источника применяется только к обновлению приложения. Ответ API ограничен 1 MiB, манифест — 64 KiB, архив — 200 MiB; лимит контролируется и при неизвестной длине ответа. Повтор запускается пользователем, без автоматического цикла запросов.

### TECH-08 — заменить последнюю фразу

Проверка и скачивание стабильного выпуска по явной команде входят в приложение согласно UPD-01–12. arm64 и минимальная macOS 26 сохраняются. Для текущей локальной поставки установка ручная; требования Developer ID и нотариализации для полноценного внешнего распространения остаются открытыми согласно `RELEASES.md`.

### AC-31 — уточнить результат

До выбора «Проверить обновление» приложение выполняет только ранее разрешённые запросы валютных данных. После команды разрешены запросы GitHub из TECH-06; нажатие «Скачать обновление» дополнительно разрешает передачу архива. Бюджет, импорт и резервные копии не используются механизмом обновления.

## Новые требования

**UPD-01.** Обновлением считается опубликованный стабильный GitHub Release, не новый коммит в main, не draft и не prerelease. Отсутствие выпуска отличается от сбоя сети. Проверка работает в заблокированном приложении.

**UPD-02.** Установленные версия и сборка читаются из `CFBundleShortVersionString` и `CFBundleVersion`. Стабильные версии сравниваются как 1–3 числовых компонента, недостающие компоненты равны нулю: 1.10 > 1.9; 1.0 = 1.0.0. При равной версии обновление доступно только при большем номере сборки. Более старая версия не предлагается независимо от её номера сборки.

**UPD-03.** В Release должны быть ровно по одному вложению `latest.json` и `BeeSave-macos-arm64.zip`. Манифест загружается по URL конкретного тега, возвращённого API, чтобы смена latest во время проверки не смешивала выпуски.

**UPD-04.** Поддерживается манифест схемы 1: `schema_version`, `version`, положительный `build`, `minimum_macos`, `architecture`, `repository`, `tag`, `asset_url`, `sha256`. Проверяются точное имя BeeSave/BeeSave, tag = v<version>, архитектура arm64, числовая минимальная macOS, URL архива конкретного тега и SHA-256 из 64 строчных hex-символов. Тег манифеста должен совпасть с тегом Release. Неизвестная схема, повреждённый JSON, отсутствие/дубли вложений и чужие адреса дают ошибку.

**UPD-05.** Для более нового выпуска сначала проверяется соответствие минимальной macOS и архитектуры. Несовместимый выпуск показывается с требованиями, без кнопки скачивания. Равная или более новая установленная версия означает «У вас актуальная версия BeeSave».

**UPD-06.** Окно имеет состояния: ожидание, проверка, актуальная версия, нет опубликованных выпусков, доступна версия, несовместимый выпуск, загрузка с прогрессом, проверенный архив, отмена, ошибка. Во время проверки/загрузки повторная команда не создаёт параллельную операцию. Остальная работа приложения доступна.

**UPD-07.** Скачивание запускается отдельной кнопкой «Скачать обновление». Архив пишется порциями во временную уникальную папку, а не в установленное приложение. При известной длине показывается процент, иначе неопределённый прогресс. SHA-256 всего скачанного файла обязан совпасть с манифестом. Пустой, слишком большой или повреждённый файл не предлагается сохранить.

**UPD-08.** После успешной проверки пользователь выбирает «Сохранить архив…» и путь в системном диалоге. Отмена диалога сохраняет возможность повторить сохранение. Запись выполняется атомарно; ошибка записи не уничтожает проверенный временный архив и показывает понятное сообщение. Finder открывается только после успешного сохранения. Окно содержит последовательность ручной установки и кнопку повторного показа архива.

**UPD-09.** «Отмена» и закрытие окна останавливают текущую операцию. Незавершённый/непроверенный архив удаляется. Завершение отменённой операции не изменяет результат новой проверки и не показывает успешную загрузку. Проверенный временный архив удаляется при закрытии окна или следующей проверке; сохранённый пользователем файл остаётся.

**UPD-10.** Сообщения различают отсутствие сети/тайм-аут, ограничение запросов GitHub, HTTP-ошибку, некорректные метаданные, несовместимость, повреждение архива и отказ сохранения. Ошибка не закрывает бюджет и допускает повтор. Диагностика не содержит финансовых данных.

**UPD-11.** Обновление не открывает/перемещает/перешифровывает базу, не меняет идентификатор `com.mubudget.app`, сервис Keychain и форматы базы/копий. Не запускает скачанный код, не отключает sandbox, Gatekeeper или TLS. Проверка SHA-256 подтверждает целостность архива относительно GitHub-метаданных, но не является проверкой доверенной подписи издателя. Автоматической установки ad hoc-архива нет.

**UPD-12.** Скрипт сборки создаёт согласованные вложения Release с постоянными именами и `latest.json` из фактического Info.plist и SHA-256 созданного архива. URL содержит конкретный тег. Репозиторий не получает финансовые данные или ключи. Публикация нового стабильного выпуска — отдельное действие после проверки сборки.

## Критерии приёмки изменения

| Критерий | Сценарий | Ожидаемый результат |
|---|---|---|
| UAC-01 | Запуск → меню BeeSave, бюджет закрыт | Есть «Проверить обновление»; отдельное окно открывается |
| UAC-02 | Новый стабильный выпуск; та же версия/сборка; более старая версия; 1.10 vs 1.9; новая сборка той же версии | Сравнение выполняется по UPD-02 |
| UAC-03 | Требование более новой macOS или другой CPU | Требования видны; скачивание недоступно |
| UAC-04 | Нет Release (404 API); draft/prerelease; отсутствует/дублируется вложение; разные теги; неверный JSON/схема/репозиторий/URL | Нет ложного предложения установки; причина объяснима |
| UAC-05 | Офлайн, тайм-аут, HTTP 500, 403/429; повтор | Ошибка/ограничение показаны; бюджет работает; повтор возможен |
| UAC-06 | Скачать реальный GitHub-архив | Файл непустой; SHA-256 совпадает; результат «Архив проверен» |
| UAC-07 | Повредить архив/оборвать загрузку/превысить лимит | Проверенного результата нет; временные файлы удалены |
| UAC-08 | Повторная команда во время работы; отмена и новая проверка; закрытие окна | Одна операция; старый результат не затирает новый; частичные файлы удалены |
| UAC-09 | Сохранить, отменить выбор пути, повторить, отказ записи | Finder после успешной записи; отмена/ошибка допускает повтор |
| UAC-10 | Имеются прежняя база и копии, проверить/скачать обновление | Байты и технические идентификаторы прежних данных сохранены |
| UAC-11 | Собрать Release и повторно посчитать SHA-256 | Info.plist, ZIP, latest.json и файл суммы согласованы |

Локальные тесты воспроизводимы и не обращаются к сети. Отдельная интеграционная проверка использует реальный GitHub Release. UI-проверка проходит в отдельной UISmoke-сборке с вымышленными данными. Реальная ручная замена приложения и вход в пользовательскую базу не объявляются проверенными без выполнения этих действий.

## План реализации

1. Добавить отдельный клиент обновлений, валидацию Release/манифеста, сравнение версий и совместимости.
2. Добавить ограниченную потоковую загрузку, проверку SHA-256, очистку при ошибке/отмене и управление состояниями.
3. Добавить пункт меню и отдельное окно, сохранение архива через системный диалог, инструкцию установки и Finder.
4. Дополнить сборку выпусков генерацией постоянных вложений, обновить README/RELEASES; сохранить базовый SPEC.md.
5. Пройти локальные, сетевые и UI-проверки; собрать архив и зафиксировать фактические результаты в плане.

Источники: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [URLSessionConfiguration.ephemeral](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/ephemeral), текущие `RELEASES.md` и опубликованный `latest.json` выпуска v1.0.1.

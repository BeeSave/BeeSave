**Приёмка заказчика от 06.10.2026.** После самостоятельной проверки заказчик сообщил, что всё работает корректно, и разрешил считать 1.2.0/build 6 стабильной. Это действующее решение о статусе выпуска: тот же GitHub Release переводится в Latest без изменения версии, тега и вложений. **История поставки от 06.10.2026.** Первоначально 1.2.0/build 6 была опубликована как Pre-release с открытой системной матрицей; последней стабильной оставалась 1.1.0. После самостоятельной проверки заказчика статус той же сборки изменён на стабильный Latest согласно решению выше.

Текущий кандидат собран SDK 27.0 с deployment target 26.0, локальные сборки/тесты и запуск выполнены на macOS 27.0. По уточнению заказчика нативные проверки он выполняет самостоятельно; для запуска и своей проверки на 27 ему не требуется устанавливать 26. Проверка 26 остаётся отдельным подтверждением нижней границы поддержки и не заменяет обязательную проверку 27. Результаты самостоятельной приёмки фиксируются до публикации.

**Закреплённая интеграция.** Sparkle 2.10.0 собирается из commit `eef1a539a373c1f1a320624b1130fc5de7b2e100`; SHA-256 исходного архива закреплён в `Vendor/Sparkle/lock.json`. Два открытых патча сохраняют согласованный контракт: потоковые лимиты/адреса/тайм-ауты загрузчика и строгая проверка нового пакета после обязательной Ed25519-подписи. Проверяются Apple Team, вложенные подписи, bundle ID, версия/build, arm64, ключ обновлений и entitlements; fallback подписи запрещён. BeeSave использует публичные `SPUUpdater`/`SPUUserDriver`; патчи не подменяют установщик. Framework в Xcode имеет **Embed & Sign**, вложенные компоненты подписываются тем же сертификатом до его встраивания. Исходники и продукты сборки находятся в локальном кеше вне синхронизируемых папок; системный карантин не удаляется. До запуска установщика сохраняются бюджет и прежнее приложение; если есть открытые формы, пользователь сначала завершает их. На время подготовленного обновления записи приостановлены.

## 1. Результат и исходное состояние

После «BeeSave → Проверить обновление» пользователь видит новую совместимую версию и выбирает **«Обновить и перезапустить»**. BeeSave скачивает и проверяет выпуск, безопасно завершает работу, устанавливает новый пакет `.app` на место запущенного приложения и открывает новую версию. Распаковка и перенос приложения через Finder в обычном сценарии больше не требуются. Сохраняются бюджет, настройки, резервные копии, пароль и ключ восстановления. Обычный вход новой версии — только пароль.

Исходный опубликованный выпуск — **1.1.0, build 5**, arm64, macOS 26+. `AppUpdates.swift` проверяет GitHub Release и `latest.json`, скачивает ZIP и проверяет SHA-256; `AppUpdateView.swift` предлагает сохранить архив и вручную заменить приложение. Xcode-проект генерируется `scripts/generate_project.py`, App Sandbox и Hardened Runtime включены, подпись Release — ad hoc.

Сохранённые данные находятся вне `.app`: `StorageLocation` выбирает `BeeSave.noindex/vault.beesave` либо существующий `MuBudget.noindex/vault.mubudget` в Application Support текущего контейнера. Раскладка, фильтры и финансовые настройки находятся в зашифрованной базе; путь внешних копий сохранён как security-scoped bookmark. Сервис Keychain — `com.mubudget.local.v1`, bundle identifier — `com.mubudget.app`.

**Переход со старого механизма.** Уже выпущенная версия без установщика не сможет сама установить первое обновление 003. Пользователь один раз скачивает DMG нового выпуска с GitHub и заменяет приложение вручную; старый ZIP остаётся доступен прежнему клиенту. После установки выпуска 003 следующие совместимые выпуски устанавливаются из BeeSave. Добавление файла в GitHub Release не меняет код уже установленной версии. Этот переход входит в инструкцию и отдельную проверку сохранности данных.

## 2. Предлагаемый механизм

Использовать **Sparkle 2**, стабильную версию с поддержкой подписанного feed, не ниже 2.9; точную версию закрепить при реализации. Проверка опубликованного стабильного GitHub Release остаётся в BeeSave. Для выбранного тега Sparkle получает подписанный `appcast.xml`, выполняет проверку подписанного архива, подготовку, установку и перезапуск. `AppUpdateManager` управляет состояниями окна и подготовкой приложения к завершению; собственные операции учёта остаются в `BudgetCore`.

Sparkle предусматривает Installer XPC Service для sandbox-приложений; его интеграция и подпись должны быть проверены в нашем пакете. Это основание выбора технологии, а не утверждение о проверенной работоспособности BeeSave: [руководство по sandbox](https://sparkle-project.org/documentation/sandboxing/).

Релизный пакет и его вложенные executable/framework/XPC подписываются **Apple Development одной Team**. Xcode встраивает Sparkle через **Embed & Sign**; вспомогательные компоненты подписываются изнутри наружу перед подписью framework и приложения. Developer ID, профиль платной программы и нотариализация не являются предусловиями этого выпуска. Основной формат первой установки и последующих обновлений — **DMG**. Образ и feed подписываются отдельным постоянным **Ed25519-ключом BeeSave**; публичный ключ заранее включается в приложение, приватный хранится вне репозитория и выпусков. Эта подпись определяет доверенного издателя обновления независимо от обновления сертификата разработки. SHA-256 сохраняется для проверки артефактов и старого ZIP-клиента. Настройка Ed25519 и поддержка DMG описаны в [документации Sparkle](https://sparkle-project.org/documentation/).

**Предусловия поставки.** Нужны действующий Apple Development с закрытым ключом, постоянный ключ Ed25519, доступ к публикации GitHub и подтверждённая работоспособность конкретной сборки на поддерживаемых macOS. Отсутствие Developer ID не блокирует разработку по этому плану. Нотариализация и stapling не выполняются; выпуск явно обозначается как подписанный сертификатом разработки, без нотариализации. Действительность сертификата и возможные ограничения профиля проверяются перед выпуском; наличие бесплатного сертификата само по себе не доказывает пригодность пакета для чужого Mac.

### 2.1. Первая установка без Терминала

1. Скачать `BeeSave-macos-arm64.dmg` из GitHub Release и открыть образ в Finder.
2. Завершить прежний BeeSave, если он открыт; скопировать `BeeSave.app` из образа в постоянную папку Applications. При замене существующего приложения его данные остаются вне пакета.
3. Открыть скопированное приложение. Если macOS блокирует неизвестного разработчика, закрыть это предупреждение.
4. В «Системные настройки → Конфиденциальность и безопасность» найти действие **«Подтвердить вход» / «Все равно открыть» (Open Anyway)** для BeeSave; пользователь сам подтверждает его и последующий «Открыть», при необходимости проходит системную аутентификацию.
5. Войти в прежний бюджет прежним паролем; для базы без пароля назначить пароль с прежним ключом восстановления. После этого пользоваться «BeeSave → Проверить обновление» и «Обновить и перезапустить».

Название кнопки зависит от языка/версии macOS. Пароль системного подтверждения относится к macOS, а не к бюджету. Порядок Open Anyway и сохранение исключения описаны [Apple](https://support.apple.com/ru-ru/102445). Это действие выполняет пользователь; установщик не добавляет исключение за него.

DMG сохраняет структуру пакета, права и символические ссылки, но не заменяет Developer ID и не гарантирует доступность Open Anyway для любой заблокированной сборки. ZIP сам по себе не является доказательством повреждения приложения. Обещание «подтверждение больше никогда не понадобится» для всех будущих сборок не фиксируется как факт. Целевой результат — одно подтверждение при первой установке и следующие обновления без команд Терминала; его проверяют на скачанном образе с обычным карантином и двух последовательных обновлениях. Если macOS требует повторный Open Anyway, это считается отдельным незакрытым критерием, а не скрывается инструкцией удалить quarantine.

### 2.2. Ограничения выбранной подписи

**Загрузка Sparkle.** Ad-hoc сборка с Hardened Runtime может столкнуться с Library Validation при загрузке framework, что отмечено в [документации Sparkle](https://sparkle-project.org/documentation/). DMG это ограничение не устраняет. Технический прототип сначала проверяет рабочую конфигурацию framework/XPC с сохранённым sandbox. Этот SDD не разрешает молча отключать Library Validation: если понадобится исключение для BeeSave или другой способ интеграции, до основной реализации описать конкретное изменение и его последствия для согласования.

Прототип 05.10.2026 подтвердил ограничение для Sparkle **2.10.0** на macOS **27.0 (26A428)**: строго проверенное дерево ad-hoc подписей, sandbox и Hardened Runtime сохранены; без исключения загрузка отклоняется с `different Team IDs`. Framework и вложенные компоненты уже переподписаны ad hoc в этом прототипе; повторная ad-hoc подпись через Embed & Sign не создаёт Apple Team ID.

Заказчик остановил вариант с исключением Library Validation и поручил использовать **Embed & Sign** с собственным сертификатом. Бесплатный Apple Development создан; Team `7VXLA38J58` подтверждена полем OU сертификата. В проекте и генераторе выбран `Apple Development`, принудительное значение `-` удалено. Сертификат действителен до 05.10.2027; цепочка Apple WWDR G3 проверена штатным доверием macOS, правила доверия не ослаблены. Новый прототип подписывает хост, framework и все вложенные компоненты одной Team: строгая проверка подписей проходит, загрузка Sparkle успешна при включённых sandbox/Hardened Runtime/Library Validation. Это закрывает проверку загрузки framework, но не подтверждает установку/XPC/Gatekeeper. Доказательства — [текущий протокол](003-update-install-validation.md).

**Вход только по паролю — уточнение заказчика и замена прежнего ограничения.** Биометрический вход и вход без пароля исключены из функциональности. Из первого запуска, входа, настроек, сообщений и текущей пользовательской документации убираются их команды и упоминания, включая недоступные переключатели. Пароль обязателен; отключить его нельзя. Восстановление по отдельному ключу остаётся аварийным способом задать новый пароль, а не альтернативным обычным входом. Developer ID/Keychain не требуются для доступа к бюджету.

Совместимые поля `touchID`/`localKeyID` прежнего bootstrap сохраняются в формате 1 для чтения старых данных, но не управляют новым интерфейсом или входом. У существующей базы с паролем пароль/ключ восстановления и данные остаются прежними. Если пароля нет, пользователь вводит прежний ключ восстановления и задаёт новый пароль до открытия обычной работы; отказ не перезаписывает файл и не создаёт пустую базу. При явной смене/восстановлении пароля прежние идентификаторы и средство восстановления сохраняются, legacy-флаг биометрии отключается. Неиспользуемые записи Keychain автоматически не удаляются. Новая база всегда создаётся с паролем не короче 12 символов.

## 3. Diff требований

Базовые документы остаются историей требований. При совместном чтении 003 имеет приоритет только для перечисленных ниже пунктов. Остальные требования SPEC/001/002 сохраняются.

### GEN-04, TECH-06 из 001 — дополнить

В разрешённый обмен по явной команде пользователя входит подписанный `appcast.xml` выбранного стабильного GitHub Release. API, `latest.json`, feed и архив относятся только к `BeeSave/BeeSave`; конкретный тег фиксируется на всю операцию. Разрешённые HTTPS-домены и запрет передачи финансовых данных, cookies, пользовательских credentials и телеметрии сохраняются. Финансовые данные не попадают в запросы, feed-параметры, заметки выпуска или диагностику установщика.

Лимиты прежнего клиента сохраняются: API 1 MiB, `latest.json` 64 KiB, архив 200 MiB; для `appcast.xml` — 1 MiB. Ожидание сетевых данных ограничено 15 секундами, передача одного ресурса — 300 секундами. Контроль объёма нужен и без Content-Length. Для интеграции Sparkle эти ограничения и политика редиректов должны быть доказаны отдельным техническим прототипом; одной проверки URL в XML недостаточно. До этого нельзя объявлять сетевой контракт выполненным. Неподдерживаемые внутренние API Sparkle не используются; необходимость изменить контракт или механизм требует обновлённого SDD до основной реализации.

Фоновые проверки, системный профиль, фоновая установка при обычном выходе и сетевые запросы заметок выпуска отключены. Ссылка «Что нового» открывает страницу выпуска только по отдельному нажатию.

### TECH-08 из 001 — заменить часть об установке

Проверка, скачивание, установка и перезапуск входят в BeeSave согласно UPD/INS этого изменения. arm64, минимальная macOS 26, App Sandbox и Hardened Runtime сохраняются. Внешний выпуск 003 проходит Apple Development signing одной Team всех вложенных компонентов и всего пакета, проверку упаковки DMG и подлинности обновлений по Ed25519; Developer ID и нотариализация не требуются. Library Validation проверяется по разделу 2.2. Installer XPC имеет только необходимые для установки функции; в него не передаются база, копии, пароли или ключи.

### DATA-01/05, BAK-04/07, AUTH-02–07/10–12, TECH-04–05 и UX-05 из 002 — уточнить для обновления

Обновление заменяет пакет приложения и сохраняет прежнее расположение, формат и идентичность данных, включая существующий домен локальных preferences. Оно не является восстановлением переносимой копии, не запускает первый старт поверх существующей базы и не сбрасывает раскладку. Прежний пароль и ключ восстановления сохраняются. Установщик не пересоздаёт их; для прежней базы без пароля действует явное назначение пароля по разделу 2.2.

AUTH-02–07/10–12 и UX-01–02/08 читаются с новым правилом: единственный обычный вход — пароль, всегда после запуска/блокировки; настройки позволяют только сменить пароль. Ключ восстановления используется для явного сброса пароля и восстановления копий. UI не предлагает выбор способов входа, биометрию или автоматический доступ через системную сессию. Автоблокировка и задержка неверных попыток сохраняются. Legacy-базы проверяются на сохранность и безопасное назначение пароля, без обращения новой сборки к Data Protection Keychain.

Для выпуска 003 версии форматов базы и копий остаются прежними. Изменение схемы и миграции данных в этот diff не включены. Это позволяет проверять обновление и возврат к предыдущему пакету независимо от миграций.

### AC-31 — уточнить результат

Обновление не использует бюджет для сетевых запросов. Локально разрешены защитный зашифрованный снимок и проверка прежнего хранилища при перезапуске. Сеть и её отказы не влияют на учёт. До начала установки окно и бюджет остаются доступны.

### UPD-01–05 из 001 — сохранить, UPD-03–04 дополнить

Источником остаётся опубликованный стабильный Release, не draft/prerelease или коммит в main. Числовое сравнение версии и сборки, отсутствие понижения версии и проверки macOS/arm64 сохраняются. При выпуске номер `CFBundleVersion` всегда увеличивается.

К прежним трём вложениям добавляются ровно по одному `BeeSave-macos-arm64.dmg`, `BeeSave-macos-arm64.dmg.sha256` и `appcast.xml`. Новый клиент требует подпись feed и совпадение тега, версии, build и платформы с выбранным Release/манифестом. URL образа в feed должен точно указывать на DMG выбранного тега; подпись относится к окончательным байтам этого DMG. `latest.json` остаётся схемой 1 со ссылкой и SHA-256 прежнего ZIP; ссылки на ZIP и DMG различаются намеренно, их метаданные относятся к одному пакету приложения. Старый клиент продолжает работать по прежнему контракту. Отсутствие feed/DMG у более нового выпуска даёт ошибку поставки, а не переход к неподписанной установке. При смене latest операция завершается по изначально выбранному тегу.

### UPD-06–10 из 001 — заменить

**UPD-06.** Состояния окна: ожидание, проверка, актуальная версия, нет выпусков, доступна версия, несовместимость, загрузка с прогрессом, проверка/подготовка, готово к установке, ожидание завершения работы, установка, результат после перезапуска, отмена, ошибка. Одновременно выполняется одна операция. Процент показывается только для измеряемой фазы; подготовка и запуск имеют собственные подписи.

**UPD-07.** «Обновить и перезапустить» разрешает полный цикл скачивания и установки выбранного выпуска. До нажатия поясняется: «BeeSave закроется и откроется в новой версии. Сохранённые данные останутся на месте». DMG сначала загружается в отдельное staging-хранилище. Ed25519-подпись проверяется до монтирования/извлечения; строгая проверка сертификатной подписи пакета предшествует замене. До запуска Sparkle завершаются открытые действия и сохраняется защитная копия; на время загрузки, проверки и установки новые записи приостановлены. Это поясняется до нажатия кнопки. Отмена до передачи установки возвращает обычную работу.

**UPD-08.** После подготовки установка продолжается автоматически, если нет незавершённых действий и выполнены INS-03–08. При открытой форме/мастере или выполняющейся записи показывается предложение завершить действие; BeeSave не отбрасывает введённое и не завершает процесс принудительно. После завершения действия доступно «Установить и перезапустить». Повторное нажатие не создаёт второй установщик.

**UPD-09.** Отмена/закрытие окна до передачи установки отменяет цикл и очищает принадлежащие ему временные файлы. Отложенная установка не выполняется неожиданно при обычном выходе. У Sparkle действие dismiss может оставить установку на выход: адаптер BeeSave должен явно отменять её, когда пользователь отменил обновление. После начала замены отмена недоступна; закрытие окна не уничтожает файлы работающего установщика. Поздние события старой операции не меняют новую.

**UPD-10.** Сообщения различают сеть, rate limit, метаданные/подпись, несовместимость, нехватку места, отсутствие прав, отказ системной авторизации, невозможность завершить приложение, ошибку замены и ошибку запуска. До замены ошибка оставляет прежнюю версию и данные рабочими. Успех скачивания не называется успехом установки.

### UPD-11–12 из 001 — заменить

**UPD-11.** Новая версия устанавливается только после обязательной Ed25519-подписи DMG и строгой проверки Apple Development подписи, совпадения Apple Team, вложенного кода, entitlements, платформы, bundle identifier, версии/build и постоянного ключа обновлений. Отсутствующая Team ID, ad-hoc или чужая Team в новом пакете отвергаются. `com.mubudget.app`, database UUID, localKeyID, password/recovery envelopes, существующие записи Keychain и настройки сохраняются; новый обычный вход использует только пароль. App Sandbox, Hardened Runtime, Library Validation, Gatekeeper и TLS сохраняются. Первый ручной переход ad hoc 1.1.0 → Apple Development и доступ к прежнему контейнеру проверяются отдельно; одного bundle identifier недостаточно для доказательства сохранности. Два следующих обновления используют одну Apple Team.

**UPD-12.** Сборка выпуска создаёт DMG и совместимый старому клиенту ZIP из одного окончательного подписанного Apple Development пакета, SHA-256 каждого артефакта, `latest.json` схемы 1 и подписанный `appcast.xml` для DMG. После подписи пакета его содержимое не меняется. После упаковки подписываются окончательные байты DMG/feed; нотариализация и stapling отсутствуют. В репозиторий входят только исходники, публичный ключ, фиксированная версия зависимости и документация. Публикация стабильного выпуска разрешена только после выполнения критериев раздела 6 и плана 003.

## 4. Новые требования к установке и сохранности

**INS-01 — доверие.** Обязательны подписанный feed и Ed25519-подпись DMG, проверяемые встроенным публичным ключом. Отказ подписи всегда останавливает установку; fallback отключён. Затем строго проверяются сертификатная подпись одной Apple Team с установленным пакетом, вложенный код, runtime flags, bundle identifier, entitlements, версия/build, arm64 и неизменный ключ обновлений. Отсутствующая Team ID и исключение Library Validation недопустимы. Framework и установщик подписаны этой же Team. Developer ID и нотариализация не требуются; Ed25519 не заменяет проверки фактического запуска/Gatekeeper.

**INS-02 — область замены.** Цель — ровно пакет запущенного BeeSave в `/Applications`, `~/Applications` или другом доступном для обновления месте, подтверждённом установщиком. Другой экземпляр BeeSave не выбирается по имени. Запуск с read-only volume, из DMG или App Translocation даёт понятное действие переместить приложение в постоянное место. Ошибка доступности не приводит к созданию второго установленного экземпляра.

**INS-03 — место и права.** До завершения BeeSave проверяются возможность подготовки и замены, свободное место для нового и защитного прежнего пакетов/зашифрованного снимка. Если macOS требует разрешение администратора, используется системный диалог; приложение не собирает пароль. Отказ оставляет старую версию рабочей. При изменении прав или места после предварительной проверки установка завершается безопасной ошибкой.

**INS-04 — завершение работы.** Перед передачей управления установщику запрещаются новые изменения, завершаются подтверждённые записи, прекращаются фоновые операции и проверяется отсутствие активных мастеров/редакторов во всех окнах. Нельзя терять черновик, прерывать commit или использовать force quit. При невозможности безопасно завершить работу установка откладывается/отменяется. В момент выхода освобождается блокировка `VaultStore`; новый процесс не конкурирует за запись со старым.

**INS-05 — защитный снимок.** После остановки записей создаётся проверенная локальная копия исходного зашифрованного файла с его исходным bootstrap; для закрытой базы разблокировка не требуется. Папка имеет права 0700, файл 0600. Это отдельный снимок обновления вне обычной ротации Backups: ранее существовавшие копии и их настройки не удаляются и не меняются. Формат переносимой копии, сбрасывающий способы входа, для этого не используется. Ошибка записи/проверки снимка останавливает установку. Для нового профиля без базы шаг отсутствует.

**INS-06 — содержимое данных.** До и после фазы установки совпадают исходные байты базы и прежних копий. После открытия совпадают UUID/количества/значения счетов, всех пяти типов операций, категорий, проектов, бюджетов, отчётов, истории импорта, курсовых снимков/кеша, раскладки/фильтров, валют и настроек защиты/копий. Внешний backup bookmark и доступ по нему сохраняются. Нормальные изменения при последующей работе приложения проверяются отдельно от установки.

**INS-07 — идентичность.** Пути `BeeSave.noindex`/`MuBudget.noindex`, имена файлов, правило выбора `StorageLocation` и существующие записи Keychain не меняются. При отказе доступа к прежнему контейнеру/ключам приложение показывает ошибку и сохраняет исходные данные. Оно не создаёт пустой бюджет как успешный результат обновления. Допустимый системный запрос macOS о доступе к контейнеру при первом переходе фиксируется в инструкции и тесте.

**INS-08 — сбой замены.** Предыдущий пакет сохраняется до подтверждения запуска нового. Замена выполняется установщиком после штатного выхода старого процесса; отказ записи не оставляет смесь файлов двух версий. Сбой до завершения замены оставляет либо восстанавливает прежний целый пакет. Если процесс/система прерваны, локальная запись операции позволяет определить незавершённое обновление и безопасно предложить повтор или возврат к предыдущему пакету. Снимок не восстанавливается поверх более новых пользовательских изменений автоматически.

**INS-09 — первый запуск.** Локальная запись операции содержит только её ID, версии/build, технические пути и этап. После запуска проверяются фактическая версия/build, завершение замены и наличие прежнего хранилища. До завершения этой проверки фоновые записи курса/ежедневной копии не меняют базу. После проверки снимается блокировка обычной работы. Вход выполняется прежним разрешённым способом; установка не обходит пароль или ранее доступную аутентификацию. Если macOS блокирует перезапуск, результат остаётся незавершённым, защитные артефакты сохраняются; пользователю доступен штатный Open Anyway без команд. Сообщение об успешном обновлении показывается один раз только после фактического запуска.

**INS-10 — ошибка запуска и возврат.** Ошибка первого запуска/открытия бюджета сохраняет исходный файл, защитный снимок и предыдущий пакет; показывается путь безопасного возврата. Автоматический откат при произвольном падении новой версии не предполагается свойством Sparkle и в этот diff не включён. Возврат пакета проверяется на неизменном формате данных; существующая более новая запись пользователя не заменяется старым снимком без отдельного явного восстановления.

**INS-11 — жизненный цикл файлов.** Staging, запись операции, защитный снимок и предыдущий пакет принадлежат конкретному обновлению. Очистка не затрагивает пользовательские копии и чужие операции. При сбое защитные артефакты остаются для восстановления. Успешная операция очищает их только после проверки запуска и успешного открытия прежнего бюджета; для профиля без базы — после успешного запуска. Без открытия бюджета нет преждевременного удаления защитной копии.

**INS-12 — запрет ложной приёмки.** UISmoke проверяет интерфейс на вымышленных данных, но другой bundle identifier не доказывает сохранность рабочего sandbox/Keychain. Сквозные тесты установки выполняются на реально подписанных Apple Development пакетах с производственным bundle identifier в отдельном тестовом профиле macOS. Первый запуск проверяется с карантином после обычного скачивания в чистом профиле/на другом Mac, а не только на машине сборки. Пользовательская финансовая база не используется как тестовый стенд.

**INS-13 — упаковка.** Read-only DMG содержит один целый `BeeSave.app` и ссылку Applications для первой установки. Права исполнения, структура framework/XPC и символические ссылки сохранены; монтирование и копирование не меняют подписанное содержимое. В пакете отсутствуют development-only entitlements, тестовые переключатели и секреты. PKG, installer scripts и требование прав администратора ради первой установки не добавляются; при реальной необходимости доступа к выбранной папке действует INS-03.

**INS-14 — Gatekeeper.** Перед публикацией проверяются первый запуск через Open Anyway, повторный запуск и две последовательные замены пакета одной Apple Team с разными cdhash. Цель — не требовать повторного ручного доверия после подтверждения исходной установки. DMG, сертификатная подпись и Ed25519 не объявляются автоматически обеспечивающими этот результат. Gatekeeper не выключается, карантин/системные записи доверия не удаляются самодельными скриптами. Если повторное подтверждение неизбежно на поддерживаемой ОС, зарегистрировать невыполненный критерий и согласовать изменённое поведение до выпуска; не публиковать обещание «один раз» без проверки.

## 6. Условие завершения и публикации

Изменение готово только после IAC-01–18, полного регрессионного прогона по SPEC/001/002 с явно уточнёнными в 003 ожиданиями Apple Development/DMG поставки и входа только по паролю, системных проверок защиты/Gatekeeper, сетевых интеграций и проверки окончательного DMG и совместимого ZIP. Положительные биометрические/Keychain-сценарии сняты заказчиком; вместо них обязательны проверки пароля, восстановления/назначения пароля legacy-базе и отсутствия прежних способов входа в UI. Остальные обязательные незакрытые проверки старых отчётов приёмки включаются в регрессию этого выпуска. Подмена системной проверки локальной фикстурой или молчаливый skip недопустимы.

Заказчик согласовал SDD/план и начало реализации сообщением «Touch ID можно исключить из функциональности и везде убрать в интерфесе упоминание об этом, вход будет чисто по паролю. Скорректируй спеку в этой части и продолжай, спека и план в остальном согласованы». Публикация стабильного GitHub Release входит в разрешённый объём после успешных проверок; дополнительное согласование той же публикации не требуется. Если обязательная проверка или предусловие не выполнены, выпуск не публикуется как готовый. Версия предварительно **1.2.0, build 6**; перед фиксацией проверить реально опубликованные теги/сборки и выбрать следующий свободный номер.

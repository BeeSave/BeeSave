## 2. Решения по реализации

- Семантическую палитру и размеры собрать в общем слое оформления. Цвет текста зависит от поверхности: светлый на бирюзовом фоне, тёмный на кремовой карточке. Системные поля, меню, клавиатура и SF Symbols сохраняют нативное поведение.
- Существующий `Filters` остаётся форматом хранения. Календарь и окно фильтров работают с отдельными черновиками; применённые значения меняются только через «Применить». Поиск вариантов справочника не является фильтром операций. Пресет переводится в календарные границы при применении; при повторном открытии сохранённые даты восстанавливаются без сдвига периода.
- Для календаря использовать `Day` из ядра и явно согласованные календарные компоненты. `Day.date` соответствует UTC, а «сегодня» определяется локально: нельзя передавать полуночный UTC `Date` локальному контролу так, чтобы выбранный день сдвинулся. Ввод и отображение локализуются, хранение ISO сохраняется.
- `Reports.selected`, `Reports.rows`, `Reports.balances`, `Reports.budgetFact` и `Valuation` остаются источником выборки и сумм. Представления не считают денежные суммы через `Double`; преобразование для высоты графика выполняется после расчёта ядром.
- Границы контекста задать явно: Главная, список одного типа, история фиксированного счёта, детализация и отчёт по остаткам разрешают разные условия. Счёт истории и набор записей детализации нельзя незаметно заменить глобальным выбором.
- Черновики форм и вложенных редакторов живут в текущей сессии. Открытие дочерней формы не заменяет единственный `model.sheet` с уничтожением родительского ввода. Загружать сохранённую запись в черновик один раз, а не при каждом возвращении из дочернего окна. `AppModel.lock()` закрывает всю цепочку и очищает состояние.
- Текущие `DashboardBlock.kind`, ID, `wide`, `visible` и `ownFilters` использовать для новой сетки. Новые значения стандартной раскладки относятся к новой базе и явному сбросу. Сохранённый массив блоков существующей базы не переписывать при обновлении. Новая схема финансового контейнера для редизайна не требуется.

### 5. Упростить операции и действия со счётом

**Работы.** Разделить представления расхода/дохода и перевода, сохранив вызовы `Ledger`. Основные поля операции: сумма, счёт, категория, дата. Дополнительные группы раскрываются по запросу или при наличии сохранённых значений. Архивное значение существующей записи остаётся читаемым. Сохранение скрытой группы не заменяет её пустыми значениями.

Передавать счёт контекста в маршрут формы. Для остальных запусков находить последний успешно использованный активный счёт этого типа по сохранённым операциям; при отсутствии истории выбора и нескольких счетах требовать явный выбор. Системную «Без категории» выбирать соответствующую типу операции. Проект из прошлой операции не наследовать.

Валютная группа показывает статус снимка, источник/дату, ручной ввод и подтверждение кеша. Полученный подходящий снимок включается в черновик операции без лишней команды закрепления; сохранение происходит после общей проверки. «Сохранить без курса» — отдельный явный путь. Смена счёта/даты отменяет устаревший запрос; старый ответ не подставляется в новую пару. RUB → RUB показывает расчётное зачисление; разные валюты — один способ ввода и две итоговые суммы. Сверка с нулём закрывается без новой записи.

Сначала добавить возврат из создания счёта в операцию/перевод, затем возврат из категории/проекта в операцию и бюджет. Дочерняя форма возвращает ID созданного объекта; родительский черновик остаётся на месте и не загружается заново. При блокировке закрываются обе формы.
